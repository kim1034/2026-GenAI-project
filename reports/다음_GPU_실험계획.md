## 연구 목표와 현재 공백

주 질문은 **고정된 GUE(D)가 원형 Uniform(B)보다 동일 환경의 오류 탐지 AUROC가 높은가**이다. 주 비교는 D−B 하나로 한다. 원논문 A/B 재현과 Qwen의 공정 비교를 하나의 연구 안에 포함한다.

기존 V1.4는 공식 시험 1,319문항의 Greedy·C·D·E를 완료했지만 A와 B의 최종 시험 비교는 없다. 기존 D−C 동등성 결과는 보존하며, 이를 기존 Uniform 대비 성능 향상으로 바꿔 해석하지 않는다.

A′가 A와 동일한 설정이면 중복 생성하지 않는다. 평가 최대 263,800응답에 개발 72,000응답을 더하면 335,800응답이다. 본평가 Greedy 라벨 1,319응답과 기술 검증은 별도다. 응답 수는 실행 시간과 비례한다고 보장하지 않으며, 새 환경에서 실측하기 전 소요시간을 확정하지 않는다.

## 두 평가 경로의 구분

**원논문 재현 경로:** 논문의 해당 모델·과제 설정을 대조한다. 원문은 K=10의 다수결 답 오류를 탐지하며, 40응답에서 25회 응답 재표집하는 절차를 보고한다. 논문에 명시되지 않은 프롬프트·개입 위치·동률·INVALID·재표집 세부 규칙은 미확인으로 기록하고 확인한 뒤 고정한다. 일부 설정을 추정했다면 정확한 수치 재현을 보장하거나 원논문 전체를 재현했다고 표시하지 않는다. B가 A보다 좋지 않아도 그대로 보고한다.

**Qwen 비교 경로:** 모든 조건에서 동일한 고정 Greedy 오류 라벨을 사용한다. 기존에 사용한 개발·예시·평가 문항과 근접 중복을 제외한 GSM8K train 후보에서 새 내부 평가 1,319문항을 선정하고 ID·SHA를 봉인한다. 모델 출력이나 정답 여부로 문항을 고르지 않는다. 이는 공식 test도, 모델 사전학습 미노출이 보장된 데이터도 아니다. 미사용 문항이 충분한지 먼저 검증한다.

## 본평가 조건

| 조건 | 정의·선택 규칙 |
| --- | --- |
| A | 무잡음, T=0.5 |
| A′ | 개발 자료에서 선택한 최선 온도의 무잡음 기준선. T=0.5이면 A 재사용 |
| B | 원형 양수 Uniform U(0,α_B). 평균 제거·고정 노름 정규화를 적용하지 않음 |
| C | 기존 중심화·정규화 Gaussian, 공통 α=0.174 유지 |
| D | 기존 중심화·정규화 GUE, 공통 α=0.174 유지 |

B의 절대 세기 α_B와 C/D의 rho 기준 상대 세기는 단위가 다르므로 같은 숫자로 강제하지 않는다. C/D는 기존 고정 설정을 평가하는 것이며, 각 방법의 최대 성능을 모두 별도로 최적화한 비교라고 주장하지 않는다.

개발 B 후보는 `[0.01, 0.03, 0.05, 0.07, 0.09, 0.11]`, 온도 후보는 `[0.5, 0.6, 0.8, 1.0, 1.2, 1.4, 1.7]`이다. 이는 아직 초안이며 등록본에서 고정한다. 본평가 점수를 보고 격자를 확대하거나 세기를 다시 선택하지 않는다.

## 분석과 완료 기준

- 주 비교 D−B의 AUROC 차이와 95% 신뢰구간을 보고한다. 문제 단위의 짝지은 bootstrap을 10,000회 시도하고, 동일한 재표집 문항을 모든 조건·seed에 적용한다.
- 각 seed의 AUROC와 seed 평균을 함께 보고한다. 3seed × 1,319문항을 3,957개의 독립 문제로 취급하지 않는다. 문제 bootstrap 신뢰구간이 미래의 모든 생성 seed 변동까지 보장한다고 주장하지 않는다.
- B−A, C−B, D−C, D−A′는 기술적 보조 비교다. 보조 결과로 주 비교를 교체하지 않는다. 기존 D−C의 ±0.02 판정을 새로운 D−B에 자동 적용하지 않는다.
- 모든 문항·조건·seed·응답이 완료되고 원본·설정·문항 순서·SHA가 검증되기 전 본평가 효과를 집계하지 않는다. 중간에는 진행률과 장애만 기록한다.
- 사람의 추출 검수는 조건을 가리고 실시자·날짜·불일치·해결 과정을 남긴다. AI 검토를 인간 서명으로 기록하지 않는다.
- 실패·중단·재개·불리한 결과도 보존한다. 재개는 같은 설정·같은 난수 키로 수행한다.

## 실행 순서와 경계

1. GPU 대여 전 원문 설정 대조·모델 접근·데이터·코드·합성 검산·기록 양식을 준비하고 연구 범위를 등록한다.
2. 새 머신의 GPU와 외부 작업을 확인한다. 점유를 확인할 수 없으면 임의 종료 대신 환경을 교체한다.
3. 개발 문항으로 기술 검증과 속도·메모리 실측을 한다. 논리 응답 수와 GPU 배치 크기를 구분한다.
4. 원문 A/B 재현을 수행하고 기술 실패와 과학적 재현 불일치를 구분한다.
5. Qwen 개발 선택과 정밀도 참고 분석을 완료한다.
6. 선택값·문항 ID·실행 목록·분석 코드·모델·프롬프트·뱅크 해시를 새 연구 전용 LOCK으로 고정한다.
7. 본평가 전체를 실행하고 분석·검수·보고·백업 검증까지 마친다. GPU 반납은 사용자가 직접 한다.

E, 중심 Uniform·동일 에너지 통제, 다른 모델·과제는 기전이나 일반화 주장을 추가하기로 **실행 전에** 정한 경우에만 최종 계획에 포함한다. 결과가 좋거나 시간이 남았다는 이유로 추가하지 않는다. 사용 시간에 따른 자동 중단장치와 GPU 자동 반납은 사용하지 않는다.
