# 다음 GPU: A·B 보완 계획 — 30시간 목표 초안

작성일: 2026-11-16 (한국시간)  
설계: Astra(AI) / 구현·실행: Sol  
상태: **검토용 수정 초안, 미등록·미실행. 별도 후속 설계 사용 0/1회.**

## 범위

사용자 요청에 따라 새 평가 분할, 원논문 모델의 별도 재현 실행, A′ 온도 탐색, 새 seed 반복을 제외한다. **기존 Qwen 공식 test 1,319문항에 A와 B만 생성하고 기존 C·D·E와 Greedy를 재사용**한다. 앞선 [전체안](다음_GPU_실험계획.md)을 먼저 실행하거나 두 안을 순차 확대하는 계획이 아니다.

주 질문은 기존 Qwen 환경에서 GUE(D)와 원형 Uniform(B)의 오류 탐지 AUROC가 얼마나 다른지이다. 새 주 비교는 D−B 하나이며, 기존 시험 결과를 알고 시작한 **사후 보완 비교**임을 명시한다.

## 생성 및 재사용 목록

| 항목 | 문항 | 응답 수 K | seed set | 신규 응답 | 처리 |
| --- | ---: | ---: | ---: | ---: | --- |
| A: 무잡음, T=0.5 | 공식 test 1,319 | 8 | 0 | 10,552 | 새 생성 |
| B: 양수 Uniform U(0,α_B), T=0.5 | 공식 test 1,319 | 8 | 0 | 10,552 | 새 생성 |
| B 개발 선택: 원문 α 격자 6점 | dev_select의 고정 첫 50문항 | 각 8 | 0 | 2,400 | 새 생성 |
| C·D·E | 공식 test 1,319 | 기존 k=0..7 | 0 | 0 | 원본·해시 검증 후 재사용 |
| Greedy 오류 라벨 | 공식 test 1,319 | 기존 1 | 0 | 0 | 고정 라벨 재사용 |
| A 개발 자료 | 동일한 개발 50문항 | 기존 k=0..7 | 0 | 0 | 기존 응답 재사용 |

**신규 합계: 23,504응답.** 기술 검증의 소량 응답·노이즈 뱅크 준비·분석·백업은 별도로 기록한다. 개발 문항은 기존 ID 순서로 고정하고 정답·오류·조건별 성능을 보고 선별하지 않는다.

B의 개발 α 격자는 `[0.01, 0.03, 0.05, 0.07, 0.09, 0.11]`이다. B는 평균 제거·고정 노름 정규화를 적용하지 않는 원형 양수 Uniform이다. C·D는 기존 공통 상대 α=0.174를 유지하며, B와 단위가 다르다는 사실을 기록한다. B의 최종 선택·동률·평가 규칙은 실행 전 등록본에서 고정한다.

Astra의 권고 선택 규칙은 기존 A 기준 대비 다수결 정확도 감소 0.05 이내·INVALID 증가 0.05 이내인 후보를 대상으로, 최고 AUROC에서 0.005 이내인 후보 중 가장 작은 α를 고르는 방식이다. 후보가 모두 부적격이면 α=0.01과 `no_feasible`을 명시하고, 최적 기준선이나 재현 성공으로 표시하지 않는다. 이 초안은 격자 끝점 추가 실행을 포함하지 않는다.

## 같은 조건으로 비교하기

- 모델 revision, 프롬프트, 최대 생성 길이, dtype/backend, 주입 층, 난수 키를 기존 조건과 대조한다.
- 새 K8 물리 배치와 기존 K16의 첫8이 완전히 같은 생성 경로라고 가정하지 않는다. 고정 개발 문항에서 기존 A/C 첫8과 새 K8의 토큰·추출을 대조하고 배치 변경 영향을 기록한다. 소수 문항 통과를 전체 문항 일치 증명으로 확대하지 않는다. 설명되지 않는 차이가 있으면 원인을 해결하거나 비교 해석을 보류한다.
- 모든 조건에 논리 K=8과 같은 문항·고정 Greedy 라벨을 적용한다. C·D·E에서 결과가 좋은 8개를 고르지 않고 **k=0..7만** 사용한다.
- 기존 V1.4의 ‘두 K8 묶음 AUROC 평균’과 새 보완 연구의 ‘첫 K8 AUROC’를 같은 추정량으로 표시하지 않는다. 기존 PR6·원본 분석은 수정하지 않는다.
- 보조 비교 A/B/C/D/E와 정확도·INVALID·잘림은 함께 보고하되, 보조 결과를 보고 주 비교를 바꾸지 않는다.
- 개발 50문항만으로 B를 선택한 정밀도 한계를 밝히며, Qwen의 최적 Uniform 또는 최적 온도 기준선보다 우수하다고 확대 해석하지 않는다.

## 30시간 목표와 실행 순서

기존 A/C의 응답당 처리율을 그대로 적용한 단순 계산은 신규 23,504응답에 약 15~19시간이다. 이는 K8의 배치 효율·Uniform 실제 속도를 아직 반영하지 않은 참고값이다. **준비·실행·분석·백업을 포함해 30시간 안쪽을 목표로 삼되, 현재 수치만으로 완주 시간을 보장하지 않는다.**

1. GPU 대여 전 별도 namespace 실행기·K8 분석기·재사용 검증·기록·백업 도구를 준비한다.
2. 새 GPU 점유 상태와 기존 설정 일치를 확인하고, 고정 개발 문항의 A/B K8로 실제 속도·메모리·결정성·재개를 검증한다.
3. 문항별 실측과 뱅크 준비 시간을 포함해 전체 완료 예상 시간을 계산한다. 성능 결과와 무관하게 30시간 목표 달성 가능성을 먼저 확인한다. 초과 예상이면 긴 본실행을 시작하기 전에 사용자에게 알린다.
4. 등록한 개발 B 6조건을 완료해 α_B를 선택하고, 첫 8응답·문항 목록·설정·분석·실행 목록을 보완 연구 전용 LOCK에 고정한다.
5. A와 B의 1,319문항을 모두 완료한다. 중간에는 진행률과 오류만 기록하고, 본평가 효과는 모든 입력이 완전할 때 분석한다.
6. 기존 C/D/E 첫8·Greedy와 결합한 새 비교 표·그림·해석을 별도로 저장하고 로컬 전체 해시 검증 후 반납 준비를 알린다.

사용 시간에 따른 자동 중단장치와 GPU 자동 반납은 만들지 않는다. 사용자의 중지 요청, 하드웨어·실행·무결성 오류는 별도 기록하고, 정상 완료는 고정 실행 목록의 완주로 판단한다. 결과를 보고 문항·seed·조건을 추가하거나 유리한 표본으로 교체하지 않는다.

## 이 범위로 주장할 수 있는 것

같은 Qwen/GSM8K 환경에서 무잡음 A, 원형 Uniform B, Gaussian C, GUE D 및 기존 E의 사후 비교를 보완할 수 있다. **원논문 모델·40응답 절차의 수치 재현, 새 데이터 검증, 생성 seed 전체의 안정성, 다른 모델·과제 일반화는 이 계획에 포함하지 않는다.**

현재 문서는 Astra의 수정 권고를 기록한 초안이다. 새로운 GPU 추론은 시작하지 않았으며, 최종 등록·구현 검증이 끝난 것으로 표시하지 않는다.
