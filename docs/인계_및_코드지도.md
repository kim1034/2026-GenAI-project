# 팀원·에이전트 인계 및 코드 지도

## 1. 이 프로젝트가 검증하는 것

고정된 Qwen2.5-1.5B-Instruct로 GSM8K 답을 생성한다. 문제마다 greedy 답이 오답이거나 유효한 수로 추출되지 않으면 양성(환각) 레이블로 둔다. 같은 문제에 여러 노이즈 응답을 만들고, 답 분포의 엔트로피를 점수로 사용한다. 주 비교는 시험 분할에서 GUE 조건 D와 Gaussian 조건 C의 평균 AUROC 차이 `D − C`다. 사전 지정된 보조 비교와 조건은 `configs/base.yaml`, `configs/analysis.yaml`, 인계 문서 v1.3에 있다. 가중치 학습과 LoRA는 현재 범위 밖이다.

진실 기준: [인계 문서 v1.3](../GUE_Gaussian_환각탐지_인계문서_ClaudeCode용_v1.3.md) > [실행 계획](실행계획.md) > 코드 주석. 불일치가 발견되면 실행 전 기록하고 해결한다. test 성능을 보고 사양을 바꾸면 안 된다.

| `configs/runs/*.yaml` | 한 번의 실행을 지정하는 예시. `split`, `condition`, `alpha`, `temperature`, `basis`, `seed_set`, `row_start`, `n_rows`. |

| `reports/` | 데이터 카드, 누출, 모델 출처, 환경, 진행 기록. |

## 5. 조건과 실행 설계

- `greedy`: 레이블을 위한 온도 0, 문제당 1응답. `A`: 노이즈 없는 온도 0.5 기준선. `Ap`: 개발 분할에서 고른 다른 온도 기준선.
- `B`/`Bc`: 균등 노이즈/중심화 대조군. `C`: Gaussian. `D`: GUE 고유값 방향. `E`: GUE 주변분포를 독립 표집한 대조군. `T5`: 자유도 5의 t 분포. `S`: 희소 Gaussian. `O`, `L`, `_H` 조건은 사전 지정된 추가 비교다.
- GUE/GOE 계수는 beta-Hermite 삼대각 행렬의 고유값으로 만들고, 방향은 중심화·단위 노름화한다. `_H`는 공통 Haar 회전을 적용한다. 분포·세기 정의는 `src/noise.py`와 `configs/base.yaml`이 기준이다.
- 노이즈 주입 세기는 B/Bc의 절대 α를 제외하면 `α × ρ_l × √8960`이다. `ρ_l`은 해당 층의 개발 기준선 활성 RMS이며, 교정 전에 상대 노이즈 조건을 실행할 수 없다.
- 개발 일반 실행은 16응답, `dev_anal` 리허설과 시험은 32응답이다. 8응답을 한 subset으로 묶는다. test 32~63 응답은 사전 지정된 C/D/E 보강 전용이다.
- 문제 ID·응답 번호를 난수 키에 사용하므로 실행 순서나 재개 여부가 난수를 바꾸지 않도록 설계했다. 실측 GPU 결과로 검증할 필요가 있다.

## 6. GPU 담당자가 이어서 할 작업

1. [RunYourAI 가이드](RunYourAI_A5000_실행가이드.md)대로 A5000, CUDA, Python 의존성과 고정 모델 로딩을 확인한다. 설치 버전·드라이버·Git SHA를 환경 기록에 남긴다.
2. `dev_base` greedy로 Qwen forward와 답 추출, 반복 결정론, 층 hook 위치를 확인한다. 이 단계에서 `calibrate_rho.py`를 실행한다.
3. 노이즈 없는 `dev_base_A`와 `dev_base_C_pilot`의 뱅크·실험을 소량 검증한다. `run_experiment.py`는 설정의 응답 수를 강제하며 문제 수 제한 인자가 없다. GPU 시간 절약용 부분 실행은 코드와 로그 설계를 먼저 검토해야 한다.
4. manifest의 `elapsed_seconds`, `gpu_max_memory_bytes`, `hook_calls`와 응답 수를 확인한다. `scripts/budget.py`로 120시간 계획을 다시 계산한다.
5. 개발 실험, S 희소도·α·온도 선택, 분석 자동화를 완성하고 선택값·필수 실행 목록·설정 해시를 `LOCK.md`에 기록한다. `lock-v1` 태그는 LOCK 커밋에 붙인다.
6. 모든 LOCK 검사를 통과한 뒤에만 test를 실행한다. 필수 8조건과 결정된 보강을 완료한 다음 주 비교 D−C를 분석한다.

## 7. 재개·백업·주의점

- `run_experiment.py`는 문제별 JSON이 있으면 건너뛴다. 기존 run ID의 설정·프롬프트·뱅크 SHA가 달라지면 중단한다. 완성된 합본 JSONL의 해시도 검증한다.
- `bank/`와 `outputs/`는 Git에 올라가지 않는다. GPU 머신이 반환되기 전에 별도 저장소나 로컬로 복사하고 해시를 대조한다.
- `src/config.py`의 LOCK은 파일 하나만 만드는 절차가 아니다. 원본 검증, 설정 SHA, 깨끗한 Git 작업 트리, `HEAD == lock-v1` 커밋을 요구한다.
- 실행 코드가 존재한다는 사실과 GPU에서 검증됐다는 사실을 구분한다. 특히 Qwen 버전 호환성, 32응답의 24GB 메모리, 결정론, hook 효과, 120시간 예산은 아직 실측 전이다.
