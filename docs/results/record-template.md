# 실험 과정·결과 기록 양식

적용 대상: 다음 GPU 연구. 현재는 **양식만 준비됐고 새 실행은 없다.** 기존 V1.4의 역사적 기록과 산출물은 소급 변경하지 않는다.

## 1. 연구 단위 기록

| 항목 | 기록할 내용 |
| --- | --- |
| 연구 ID·상태 | 초안 / 등록 / 개발 / 봉인 / 본평가 / 분석 / 검증 완료 |
| 목적·주 비교 | 무엇을 검증하는지, 주 비교 하나와 보조 비교 목록 |
| 역할 | 설계·해석 Astra, 구현·실행 Sol, 실제 인간 검수자 별도 |
| 등록·변경 | 한국시간·UTC 시각, 변경 이유, 영향, 이전 문서·SHA |
| 데이터 | 출처·revision·분할·ID SHA·중복 제외·기사용 여부 |
| 평가 대상 | Greedy 오류 / 다수결 오류 등 정확한 라벨 정의 |
| 완료 기준 | 필수 조건·seed·문항·응답·분석·백업 목록 |

초안을 확정 설정으로 표시하지 않는다. ‘완료’는 승인 범위의 완료이며, 빠진 원래 가설이나 미실시 baseline까지 완료했다고 쓰지 않는다.

## 2. 실행별 원장

| run ID | 단계 | 모델·조건 | split·n | seed·K | 설정 SHA | 상태·진행 | 원본·로그·manifest |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 미실행 | — | — | — | — | — | 등록 전 | — |

각 run에는 모델·tokenizer revision, 프롬프트 SHA, dtype·backend, 주입 위치·방식, α의 정의·값, 온도, 길이 상한, 논리 K와 물리 배치, 난수 키를 함께 보존한다. 파일 이름뿐 아니라 실제 내용의 해시로 설정을 연결한다.

## 3. 진행·장애·재개 이력

| 시각 KST / UTC | run·invocation ID | 관측 사실 | 조치·이유 | 검증 근거 | 다음 상태 |
| --- | --- | --- | --- | --- | --- |
| 미실행 | — | — | — | — | — |

- 관측한 PID·GPU 사용률·완료 문항 수와 추정 원인을 구분한다. PID가 보인다는 이유만으로 진행했다고 쓰지 않는다.
- 중단 시 종료 코드, 마지막 원자 저장, 재개 전 파일 수·SHA, 재개 후 첫 완료를 보존한다. 재개 시 설정·seed를 바꾸지 않는다.
- 시간은 실행 전체와 각 invocation을 구분한다. 기존 D의 마지막 manifest 경과 시간은 재개 후 신규 1,003문항에 대한 것이므로 전체 1,319문항 수행 시간으로 쓰지 않는다.
- 환경 이상과 실제 설치자·원인을 구분하고, 확인하지 못한 사실을 단정하지 않는다.

표의 수치는 원본 JSON·CSV에서 작성한다. 표시할 때만 필요한 자릿수로 반올림하고 원본 수치는 보존한다. 결과가 없는 칸에는 0이나 가상의 값을 넣지 않고 ‘미실행·미분석’으로 기록한다.

## 5. 검수·결론·발표 자료

- 추출 검수: 선정 규칙, 검수자, 조건 가림 여부, 검수 일시, 일치·불일치, 해결 내용을 기록한다.
- 결론: 관측값 → 통계 근거 → 가능한 주장 → 할 수 없는 주장 순서로 쓴다.
- 재현 비교: 원문 설정과 다른 항목, 재현된 범위, 재현 불일치도 함께 보고한다.
- 발표: 연구 질문, 조건·분할, 주요 결과 표·그림, 실패·변경, 한계, 재현 자료 링크를 준비한다.
- 전체 결과가 나올 때까지 본평가의 유리한 부분 결과를 골라 발표하거나 설정을 바꾸지 않는다.

## 6. 백업·종료 기록

필수 원본·설정·뱅크·로그·분석·코드 bundle의 파일 목록과 SHA를 원격·로컬에서 대조한다. 누락·불일치·제외 범위와 로컬 실제 경로를 남긴다. 읽기 검증 전에는 반납 준비 완료라고 기록하지 않으며, 실제 반납과 반납 가능 안내를 구분한다. 개인키·비밀번호·토큰은 문서와 자료 묶음에 포함하지 않는다.
