# GUE와 Gaussian 교란 실험 실행 계획

이 계획은 [인계 문서 v1.3](../GUE_Gaussian_환각탐지_인계문서_ClaudeCode용_v1.3.md)를 실행 순서로 옮긴 것이다. 사양이 충돌하면 인계 문서의 v1.3 데이터 출처 변경과 Part 2를 우선한다. **모델 가중치는 학습하지 않고 고정한다.** 데이터와 개발 분할을 고정한 뒤 노이즈 주입과 추론을 구현한다. 시험 분할의 모델 출력과 성능은 설정을 LOCK하기 전까지 확인하지 않는다.

## 1. 데이터 확인

### 1.1 원본과 형식 고정

1. OpenAI 공식 저장소의 고정 commit과 로컬 JSONL의 Git blob SHA를 대조한다. 차이가 있으면 인계 문서 §5.1에 맞는 원본을 다시 확보하고 변경을 기록한다.
2. 채택한 원본의 저장소 revision 또는 Git commit, 파일 SHA-256, 취득 경로를 기록한다. 이후 실험은 `data/raw/`의 고정 파일만 읽는다.
3. train 7,473행과 test 1,319행, 각 행의 `question`·`answer` 필드, 질문의 비어 있지 않음을 확인한다.
4. 모든 정답에서 마지막 `####` 뒤를 읽어 쉼표를 제거하고 `Decimal`로 변환한다. 원문 정답과 변환값을 별도로 보존한다. 8,792행 전부 성공해야 한다.

**완료 기준:** 원본 commit과 파일 해시가 기록되고, 행 수·필드·정답 파싱 오류가 0건이다. 현재 기준을 충족했다.

### 1.2 프롬프트 예시와 누출 점검

1. Wei et al.의 GSM8K 8-shot 사고 사슬 예시를 `prompts/gsm8k_8shot.json`에 원문과 원래 순서로 고정한다. 예시별 질문·풀이·최종 답 형식과 파일 해시를 확인한다.
2. 질문 정규화는 소문자화, 연속 공백 압축, 앞뒤 공백 제거로 고정한다. 단어 5-gram 집합의 Jaccard 유사도를 구현한다.
3. train 전체에서 8-shot 예시와 질문이 같거나 Jaccard가 0.5 이상인 문제를 제외한다. 같은 기준으로 test 1,319문제와 가까운 train 문제도 제외한다.
4. test와 8-shot 예시 사이의 최대 유사도 및 0.5 이상인 test ID를 기록한다. 해당 test 문제는 공식 시험 집합에서 제거하지 않고, 추후 민감도 분석 대상으로 표시한다.
5. 제외 건수와 ID, 개발 후보와 test의 최대 유사도를 `reports/leakage.md`에 남긴다. test **질문 텍스트만** 누출 점검에 사용하고 모델 출력은 생성하지 않는다.

**완료 기준:** 중복 검사 기준과 제외 목록이 재현 가능하고, 선택된 개발 300문제와 test 사이에 Jaccard 0.5 이상인 쌍이 없다.

### 1.3 개발 분할과 데이터 카드

1. 남은 train 후보를 전역 시드 2026의 `rng_for(1, 0)`으로 섞어 앞의 300문제를 고른다. 이를 `rng_for(1, 1)`로 다시 섞어 `dev_base` 50, `dev_select` 200, `dev_anal` 50으로 나눈다.
2. 원본 인덱스를 ID로 사용한다. 개발은 `train-00000` 형식, 시험은 `test-0000` 형식이다. 분할 목록 안의 위치를 ID나 난수 키로 사용하지 않는다.
3. `data/splits/{dev_base,dev_select,dev_anal,test}.ids`를 저장하고 중복·누락·개수·train/test 분리를 검사한다. 분할 파일의 SHA-256을 기록한다.
4. `reports/data_card.md`에 분할별 문제 수, 정답 분포, 원본·분할 해시를 기록한다. 질문 토큰 길이는 모델 토크나이저를 확보한 뒤 채우고, greedy 정확도·무효율·레이블 비율은 GPU 기준선 실행 뒤 채운다.

**완료 기준:** 개발 300문제가 정확히 50/200/50으로 나뉘고, ID·해시·누출 보고서가 고정된다. 이때까지 test 모델 실행은 없다.

## 2. 데이터 확인 후 실험 구현

| 순서 | 구현 내용 | 실행 전 확인 |
| --- | --- | --- |
| 1. 저장소·설정 | `configs/base.yaml`을 v1.0 부록 B에 v1.2 §V13.1을 덮어써 작성한다. 원본 revision, 분할·프롬프트 경로, 시드, 조건, GPU 예산을 설정에 둔다. 환경 정보를 기록한다. | 설정에 v1.0의 낡은 `decode.k_generate`와 `noise.conditions`가 남지 않는다. |
| 2. 데이터·평가 함수 | 로컬 JSONL 로더, 답 추출, greedy 정답 판정, 8개 답의 엔트로피, AUROC와 4묶음 평균, 쌍체 부트스트랩, 공통 α 선택 규칙을 구현한다. | 작은 손계산 예시로 정답 파싱·점수·AUROC·난수 재현성을 검산한다. |
| 3. 모델 실행 | Qwen2.5-1.5B-Instruct를 고정 revision·float32·eager로 로드한다. 자체 디코딩 루프를 만들고 개발 16행, 리허설·시험 32행을 지원한다. prefill에서는 마지막 위치에만 `lm_head`를 적용한다. | 같은 설정의 반복 출력이 같고, 마지막 위치 로짓이 기준 계산과 일치한다. `model.generate()`는 샘플링에 쓰지 않는다. |
| 4. 노이즈와 hook | GUE·Gaussian·대조군·균등·t5 및 선택 조건의 생성 코드를 만들고, 노이즈 뱅크를 미리 저장한다. 20~28층 `mlp.act_fn` 출력에 응답마다 고정된 노이즈를 주입한다. S의 희소도는 dev 기울기 진단 후 정한다. | 뱅크 분포·크기·방향 조작 점검과 hook 위치·세기 점검을 통과한다. |
| 5. 실행기·진단 | 문제 원본 ID 기반 난수 키, 재개 가능한 출력, manifest, 설정 해시, test LOCK 가드, 기울기와 `d_eff` 진단, 시간·예산 기록을 구현한다. | 중단·재개해도 중복 행이 없고 같은 키는 같은 출력을 낸다. LOCK 전 test 실행은 즉시 거부한다. |
| 6. 개발 실행 | dev greedy와 기준선, 파일럿, `dev_select`에서 공통 α·B·S의 α 및 최적 온도 A′를 선택한다. dev 분석으로 검정력과 P1 보강 여부를 결정하고 GPU 시간을 실측해 120시간 예산을 갱신한다. | G1~G4 및 보고서 초안 생성이 통과하고 선택값·실행 목록이 `LOCK.md`에 고정된다. |
| 7. 시험·분석 | LOCK 후 test greedy·기울기 진단, 필수 8조건, 결정된 P1 보강을 실행한다. 완료된 뒤에만 주 비교 D−C와 사전 예측을 분석한다. P2는 사전 순서와 시간 규칙에 따라 실행한다. | 필수 출력의 문제·행 수와 manifest 해시가 일치한다. 결과를 보고 설정이나 P2 순서를 바꾸지 않는다. |
| 8. 재현·보고 | 새 환경에서 일부 조건을 재실행하고 표·그림·변경 기록·한계를 보고서에 정리한다. | G6 재현 점검 및 두 사람의 교차 검수를 마친다. |

큰 테스트 묶음을 먼저 만드는 대신, 각 단계의 결과를 믿는 데 필요한 검산을 함수 완성 직후 수행한다. 인계 문서가 요구한 게이트와 LOCK 절차는 그대로 유지한다.
